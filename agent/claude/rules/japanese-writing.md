## 日本語の書き方

このルールは、人が読む日本語すべてに適用します。PR説明文・Issueコメント・チャットでの返答・markdownドキュメント・コード中の日本語コメント・Artifact として公開するページ、いずれも対象です。

浮く語を禁止語としてチェックする hook が入っています（`~/.claude/hooks/ja_style_hook.py`）。差し戻されたら、警告に出ている言い換えに従って直してください。回避する方向で考えないこと。

hook が拾えるのは単語だけなので、以下は自分で気をつけてください。

### 情報の役割に名前を付けず、内容をそのまま書く

「根拠は〜です」「前提として〜」「論点は〜」のように、その文が議論で果たす役割を先に名指しする書き方をやめてください。調べた事実や考えたことをそのまま書けば、役割は読めば伝わります。役割を名指しする構えを取ると、それを指す抽象名詞（根拠・前提・観点・論点・帰結・本質・妥当性・裁量）が必ず必要になり、文章が不自然になります。

```
✗ この判定を変えた根拠は、呼び出し元で user_id を信用していないというコメントです
○ 呼び出し元に「user_id は信用するな」とコメントが入っていたので、それに合わせました

✗ 新旧のパリティを検証しました
○ 新旧で同じ結果になるか確認しました。件数も内訳も一致しています
```

### 具体形があるなら具体形を選ぶ

総称で書いたりして、言葉の情報量を削りすぎないようにしてください。経路→「CDN→アプリサーバーの流れ」、上流→「呼び出し元」、旧経路→「v1 API 側」、集合→「対象のユーザー群」のように、実際の名前で書いてください。

### 単独で使わない言葉

複合語なら自然でも、単独の名詞として書くと違和感が出る言葉があります。「命名規約」「回帰テスト」「境界値」は使えますが、「規約に反する」「回帰した」「境界を決める」は避けてください。
「面」も同じです。「出面」「画面」は使えますが、「触れる面」「アクセスできる面」のような書き方はせず、「読めるもの・書けるもの」「できること」と書いてください。

### 飾りのラベルも日本語で

見出しの上の小さなラベル、カードのラベル、図のキャプションを英語にしないでください。layer 2 → 「2層目」、rule 3 → 「ルール3」、Chapter 01 → 「第01章」、Reading order → 「読む順序」。コードの言語名（js, swift）や製品名・API名は例外です。

### 定義に忠実な言い方より、読んで分かる言い方

冒頭・リード文・見出しでは、仕様どおりの言い方を避けて、動作で書いてください。正確さが要るなら本文の表や注で補います。

```
✗ window.parent で触れる面は仕様で列挙された固定の集合です
○ window.parent 経由で読めるもの・書けるものは決まっていて、それ以外に触ると SecurityError になります
```

### 内輪の番号・レイヤー名は書き下す

「ステップ3」「L1」のようなプロジェクト資料の中でだけ通じる番号やレイヤー名は、資料の外（シート項目・PR本文・チャット）に出すときに意味を書き下してください。

### 指示語を重ねない

「どの」「この」「それ」「どれか」が連なると読み返しが必要になります。指示語を具体名に置き換えてください。

```
✗ どの章もこの軸のどれかを掘っています
○ 以降の章は、上記したトピックをひとつひとつ詳しく扱います
```
