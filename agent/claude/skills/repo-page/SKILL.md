# repo-page

ディレクトリ配下のファイルを1枚のHTMLに詰めて、GitHub のファイルビューのように読めるページを作る。レポート本文だけを Artifact にすると、そこから参照しているSQLやスクリプトが手元に残って読み手に届かない。それを避けるためのスキル。

再編集する用途は考えていない。読む・コピーする・出どころを確かめる、の3つだけができる。

## 作るもの

```
<出力先>.html   ← 1ファイル完結。これを Artifact で公開する
```

HTMLの中にファイルの中身がそのまま入る。外部への通信もCDNもない。

## 手順

### 1. 対象を決めて中身を見る

```bash
find <対象ディレクトリ> -type f -not -path "*/.git/*" | head -60
du -sh <対象ディレクトリ>
```

ファイル数が100件を超えるとき、あるいは 20MB を超えるときは、どこまで載せるかをユーザーに聞く。サブディレクトリを1つに絞ったほうがよいこともある。

### 2. ビルドする

```bash
python3 <このスキルのディレクトリ>/build.py <対象ディレクトリ> \
  -o <スクラッチパッド>/<topic>.html \
  --subtitle "<1行の説明>"
```

`<このスキルのディレクトリ>` はスキルを読み込んだときに示されるパス（`~/.claude/skills/repo-page` に置いてあればそこ）。`build.py` と `template.html` は同じディレクトリにあり、そこを動かさなければ他のマシンでもそのまま動く。Python 3.8 以降だけ要る。

`<スクラッチパッド>` はシステムプロンプトが示すスクラッチパッドのディレクトリ。**対象ディレクトリの中に出力しない**（リポジトリに生成物を残すかどうかはユーザーの判断。聞いてから置く）。

`-o` を省くと `<対象ディレクトリ>/repo-page.html` に出る。既にファイルがあるときは止まるので、`--force` を付けるか別の名前にする。

### 3. 出てきた警告を読む

build.py は次を標準出力に出す。**全部読んでから次に進む。**

| 行 | 意味 | やること |
|---|---|---|
| `除いた: …` | 鍵・トークンらしいものがあったので中身を載せていない | そのままでよい。報告に書く |
| `要確認: …` | メールアドレス・電話番号・パスワードらしい値が見つかった | ファイルを開いて自分で確かめる。実在の個人のものなら `--exclude` を付けて作り直す |
| `一部だけ: …` | 大きいので先頭だけ載せた、または開けない形式 | 報告に書く。全体が要るなら `--max-file-bytes` を上げる |
| `注意: 出力が12MBを超えた` | Artifact の上限（16MB）に近い | 画像や大きいCSVを `--exclude` で落とす |

`要確認` は誤検出もある（UAの一覧、サンプルの `password = 'xxx'`、公開情報のメールアドレスなど）。中身を見ずに落とすのも、見ずに載せるのもしない。

### 4. Artifact で公開する

```
Artifact(file_path: "<出力先>.html", favicon: "📁",
         capabilities: {"downloads": true},
         description: "<何のディレクトリで、何が入っているか1文>")
```

`capabilities` の `downloads` は省かない。これが無いと、ページの「保存」と「まとめて保存」が無反応になる（Artifact のビューはページからのダウンロードを止めているため）。宣言しておけば、読み手が押したときに確認ダイアログが出てファイルが手元に落ちる。

`<title>` はビルド時に入っている（`--title` 未指定なら README.md の先頭のh1、無ければディレクトリ名）。タイトルを変えたいときは `--title` を付けて作り直す。

### 5. 報告する

```
公開: <URL>
ファイル: 18件（markdown 4 / sql 6 / python 3 / csv 3 / png 2）
除いた: .env（鍵が入りうる名前）
一部だけ: data/events.csv（先頭200行。全体は12万行）
要確認だったもの: sql/seed.sql のパスワードらしい値 → テスト用の固定値だったので載せた
```

除いたもの・一部だけのものは必ず列挙する。**報告せずに落とさない。**

## オプション

| オプション | 既定 | 用途 |
|---|---|---|
| `-o PATH` | `<src>/repo-page.html` | 出力先 |
| `--title T` | README.md の先頭h1 | ページ名。タブとギャラリーに出る |
| `--subtitle S` | なし | ヘッダーに出る1行 |
| `--source S` | リポジトリ名/ディレクトリ名 | ヘッダーに出す出どころ |
| `--entry PATH` | README.md | 最初に開くファイル |
| `--exclude GLOB` | なし | 落とすもの。パスでもファイル名でも効く。何度でも渡せる |
| `--include GLOB` | なし | これに一致するものだけ載せる |
| `--allow PATH` | なし | 既定で落ちるファイルを名指しで載せる（`--allow config/.env.example`） |
| `--max-file-bytes N` | 262144 | これを超えるテキストは先頭だけ |
| `--preview-lines N` | 200 | 先頭だけ載せるときの行数 |
| `--max-image-bytes N` | 1572864 | これを超える画像は載せない |
| `--force` | — | 出力先の上書きを許す |
| `--print-json PATH` | — | 埋め込んだデータをJSONでも書き出す（中身の確認用） |

## 既定で載らないもの

- `.git` `.venv` `node_modules` `__pycache__` `dist` `build` `.terraform` `site-packages` などのディレクトリ
- ロックファイル（`uv.lock` `package-lock.json` ほか）、`.pyc` `.so` などのビルド結果
- 圧縮ファイル、動画・音声、フォント、`.parquet` `.pkl` `.sqlite`、`.har`、`.map`、`*.min.js`
- `.env*` `*.pem` `*.key` `credentials*` `*service-account*.json` などの名前のファイル（一覧には「除外」として出るが中身は入らない）
- 中身に秘密鍵・AWSキー・GitHubトークン・Slackトークン・JWT・接続文字列のパスワードらしい文字列があるファイル
- PDF・Excel・Word（一覧には出るが開けない旨の説明になる）

必要なものが落ちたときは `--allow <パス>` で名指しする。

## ページでできること（読み手への説明用）

- 左にファイル一覧。ディレクトリは折りたためる。README とmarkdownが上に来る
- markdown は本文としてレンダリング（表・コードブロック・タスクリスト・mermaid対応）。「原文」タブで元のテキストも見られる
- markdown の本文幅は「普通 / 広め / 全幅」で切り替えられる（76ch / 108ch / 画面いっぱい）。選んだ幅はその読み手のブラウザに残る
- markdown 内の相対リンクは同じページの別ファイルへ飛ぶ。相対パスの画像は埋め込み済みの画像に差し替わる
- 見出しが2つ以上あるmarkdownでは、左下に見出しの一覧が出る
- CSV・TSV は表として表示（800行まで）。「原文」タブもある
- HTMLファイルは「ソース」と「表示」（枠内でそのまま描画）を切り替えられる
- 画像はクリックで原寸と縮小を切り替え
- 検索ボックス1つで、ファイル名と全ファイルの中身を同時に検索。結果から該当行へ飛ぶ
- ボタン: 内容をコピー / 保存 / パスをコピー / GitHub（追跡されているファイルは、その時点のSHAで固定したリンク）
- ヘッダーの「全文をコピー」で、全ファイルをパス見出し付きの1つのテキストにしてコピー
- ヘッダーの「まとめて保存」で、全ファイルをディレクトリ構造ごと zip にして保存
- 保存できる拡張子は claude.ai 側で決まっていて、`.sql` `.py` `.vue` などは対象外。そういうファイルは `q.sql.txt` のように `.txt` を足して保存される（zip の中では元の名前のまま）
- キー操作: `/` で検索、`j`/`k` でファイル移動、`Esc` で検索を消す
- ライト・ダークどちらのテーマでも読める。スマホでは一覧がドロワーになる

## やらないこと

- `template.html` を直に編集して出力を作る（build.py を通す。テンプレートを直したいときは報告してユーザーに委ねる）
- 警告を読まずに公開する
- 個人情報の載ったファイルを確認せずに載せる
- 対象ディレクトリの中に出力を置いたまま放置する（置くならユーザーに聞く）
- 外部CDN・外部フォント・fetch の追加（`file://` で開いても動く形を崩さない）
