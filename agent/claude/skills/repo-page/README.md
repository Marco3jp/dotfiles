# repo-page

レポートと、それを出したクエリ・スクリプトが同居しているディレクトリを、1ファイル完結のHTMLファイルブラウザにして Artifact で公開するスキル。

## 何をするか

`notes/<topic>/` のような調査メモのディレクトリを丸ごと1枚のHTMLに詰める。左にファイル一覧、右に中身。markdown はレンダリング、CSVは表、画像は埋め込み、それ以外は行番号付きのテキスト。

レポート本文だけを Artifact にすると、そこから参照しているSQLやスクリプトが手元に残って読み手に届かない。それを避けるためのもの。読む・コピーする・出どころを確かめるだけができて、再編集はできない。

## 使い方

```
/repo-page notes/latency-review
```

自然文でも動く:

```
notes/latency-review をページにして渡せるようにして
```

## 中身

| ファイル | 役割 |
|---|---|
| `SKILL.md` | エージェント向けの手順 |
| `build.py` | ディレクトリを走査してHTMLを組み立てる。これを実行する |
| `template.html` | 出力のひな形。直接編集して成果物を作らない |

`build.py` と `template.html` は同じディレクトリに置いておく必要がある。Python 3.8 以降だけあれば動く。

```bash
python3 <このディレクトリ>/build.py <対象ディレクトリ> -o out.html --title "..."
```

## 載せないもの

`.venv`・`node_modules`・ロックファイル・バイナリは拾わない。`.env` や `*.pem` は一覧に「除外」と出すだけで中身を入れない。中身に秘密鍵・AWSキー・GitHubトークン・JWTがあるファイルも同じ。

メールアドレスや電話番号が一定数あるファイルは「要確認」として出すだけにしてある。ページから外すかどうかは中を見て決める（公開されている問い合わせ先のように、載せてよいものもある）。

## 出力を置く場所

既定では対象ディレクトリの中に `repo-page.html` を作るが、スキルの手順ではスクラッチパッドに出すようにしている。リポジトリに生成物を残すかどうかは依頼した人に確認する。
